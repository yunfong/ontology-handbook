8.3 建模与工程工具链

编写 → 校验 → 编译 → 发布 → 消费

这一格解决的是「本体这件事在工程上怎么可行」。八个项目分两类：编辑器（Protégé、WebVOWL、Ontosphere、OrionBelt、Mentor）产出即交付物；编译器（LinkML）产出是中间物，再由生成器分发到各目标格式。这两类不能互相替代，但一个组织只需要一个「源」。

关键判断：schema 的单一源应该是人可读、可 diff、可编译的东西，而不是某个编辑器工程文件。

LinkML

S
linkml/linkml
★ 6772021-03-16PythonApache-2.0
YAML 优先的建模语言。仓库里有 41 个生成器模块：JSON Schema、SQL DDL、OWL、SHACL、Shex、RDF、YARRRML、ER 图、PlantUML、Markdown 数据字典、多语言代码。它回答的是「谁是 schema 的单一源」，而不是「怎么画图」。
何时采纳要给一套对象模型找一个可 diff、可 review、可多目标编译的源头时。

Protégé

S
protegeproject/protege
★ 1,6172013-08-20JavaNOASSERTION
OWL 桌面编辑器二十年的事实标准，分类树、公理编辑、推理机接入都成熟。但它是安装包、无端点、无批量校验，天然只能当「建模期」工具。
何时采纳需要人工审视分类是否合理、公理是否矛盾时。

Ontology Development Kit

A
INCATools/ontology-development-kit
★ 3872015-12-15DockerfileBSD-3-Clause
把本体开发做成流水线：固定镜像、按一份配置生成仓库骨架、生成禁止手改的 Makefile、内置 CI / QC / 发布 / 动态 import。生物医学界把它跑成了工业线。
何时采纳只想借它的三条纪律（生成物与手工物分离、配置驱动骨架、QC 必须是 CI job）时。

Sparnatural

A
sparna-git/Sparnatural
★ 3152018-08-31TypeScriptLGPL-3.0
用 SHACL 配置出来的可视化 SPARQL 查询器。三个设计值得抄：配置即 schema 所以非法组合在界面上不可表达；facet 保证不会产出零结果查询；生成的 SPARQL 先给人看再执行。
何时采纳要把「写查询」降级成「点选」、又要保证结果不为空时。

WebVOWL

B
VisualDataWeb/WebVOWL
★ 1,0212015-04-17JavaScriptMIT
把 OWL 本体画成可交互的网页图，节点按类层次布局，用于评审与沟通而非开发。
何时采纳需要一张「不装软件就能打开」的本体全景图时。

Ontosphere

B
ThHanke/ontosphere
★ 2552025-09-03TypeScriptNOASSERTION
浏览器内的 RDF / 本体编辑器，可从文件、URL 或 SPARQL 端点装载，带 OWL-RL 推理。两个机制值得抄：RDFC-1.0 规范化加 SHA-256（解决空白节点标号抖动导致 diff 全红），以及带 justification 的诊断对象。
何时采纳需要让非工程角色在浏览器里改本体时。

OrionBelt Builder

B
ralforion/orionbelt-ontology-builder
★ 2182025-11-25PythonNOASSERTION
Streamlit + rdflib 的浏览器工作台，OWL-RL 推理、SKOS 校验。设计上有两点很实：分级校验（错误 / 警告 / 提示）与「带理由的豁免」，且故意不提供一键全修复。
何时采纳设计「校验结果怎么让人看懂、怎么允许合理例外」时。

Mentor for VSCode

B
faubulous/mentor-vscode
★ 492023-09-23TypeScriptGPL-3.0
VSCode 内的 RDF / 本体编辑支持，边写边校验，把建模放回工程师日常的窗口。
何时采纳团队是工程师文化、不希望引入新 IDE 时。
