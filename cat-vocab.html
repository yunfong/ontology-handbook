8.6 领域词表与本体资产

别人已经付出的建模劳动，能不能借

这一格不是工具，是资产：术语、上位词、公理、标识符规范。借用时要区分三样东西的价值：公理（需要推理机才能兑现）、分层（业务系统真正需要的）、标识符（最容易被低估）。一个反复出现的教训是：标识符必须落在你自己能治理的命名空间里，否则词表还活着、ID 已经死了。

判据：整包引入几乎总是错的；摘术语、抄分层、借命名规范才是对的。

FIBO

A
edmcouncil/fibo
★ 7842014-02-07ShellMIT
金融业务本体，OMG 标准化、季度发版、MIT 许可。体量以 RDF 为主（约 440 MB），按业务实体、公司行为、衍生品、证券等十个域组织。它以合约与工具为中心，客户域很薄，且建模的是欧美市场结构。
何时采纳需要金融术语的权威定义与稳定 IRI 时，摘用而非整包引入。

Schema.org Types

B
google/schema-dts
★ 1,2542018-11-29TypeScriptApache-2.0
Schema.org 词表的 TypeScript 类型定义，覆盖全网最常见的实体与关系。它是事实上的「轻本体」：没有公理，但标识符稳定、被搜索引擎与大量工具消费。
何时采纳需要对外导出 JSON-LD、让第三方能理解你的对象时。

Awesome Ontology

B
ozekik/awesome-ontology
★ 7342019-03-01—CC-BY-4.0
本体资源清单，价值在编辑动作而非链接本身：给每个停更项目标注停更年份，并记录「某个词表被合并进另一个」这类消亡方式。
何时采纳做技术尽调、需要快速判断某个词表还活着没有时。

Awesome Ontologies (NCOR)

B
NCOR-Organization/awesome-ontologies
★ 252025-04-29PythonMIT
面向语义互操作的本体清单，BFO 一脉，要求贡献者附上可下载的实物文件而不只是链接。规模小、维护集中。
何时采纳需要 BFO 系上位本体的索引时。

GO Tools

C
tanghaibao/goatools
★ 9092010-01-15PythonBSD-2-Clause
Gene Ontology 的词条处理库（本身不是词表）。两个机制可借：slim 把细词归并到粗词；传播计数会导致父词虚高，需要专门的消除算法。
何时采纳处理层级汇总、又不想让父节点数字虚高时。

AudioSet Ontology

C
audioset/ontology
★ 7152016-09-02——
音频事件分类本体，结构干净：七字段的类记录，带正负例。它同时是一个警示：标识符锚在已关停的 Freebase 上，说明「稳定 ID」必须落在自己能治理的命名空间里。
何时采纳需要一份结构极简的本体样例时。

KBpedia

C
KBpedia/kbpedia
★ 2412016-09-19——
KKO 通用知识本体与跨源 linkage 映射，2020 年后停更。README 内部数字自相矛盾（5.8 万概念 / 54k 文件 / 「30 来个」），是死库文档漂移的实证。
何时采纳需要跨领域上位词表、且能容忍文档不一致时。

Open Digital Twins (Building)

C
Azure/opendigitaltwins-building
★ 1772020-06-03—MIT
DTDL 加 RealEstateCore 的楼宇与不动产数字孪生本体。一个细节值得学：标识符里编码了版本（dtmi:...;1），使「同一实体的不同版本」天然可区分。
何时采纳设计「标识符要不要带版本」时参考。
