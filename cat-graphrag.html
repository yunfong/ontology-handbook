8.5 图谱检索与 GraphRAG

检索的邻居，不是本体的替代品

这一类严格说不属于本体，但 2026 年的「本体热」有一半是被它带起来的，必须单列并划清边界。GraphRAG 解决「检索粒度与多跳」，本体解决「语义一致与约束」。两者的关系是共存：本体给对象类型与主键，检索给 chunk 到实体的索引，两边靠 ID 对齐。

三条判据：问「还要看什么」→ 检索；问「什么必须为真」→ 约束；出现审批、回滚、对账 → 检索出局。

Microsoft GraphRAG

A
microsoft/graphrag
★ 36,4972024-03-27PythonMIT
图式 RAG 的参考实现：抽实体与关系、做社区划分、生成分层摘要。README 自述已「largely in maintenance mode」，代码是 demonstration 而非官方支持产品。
何时采纳读它的论文与 prompt 设计，不要直接引代码。

LightRAG

B
HKUDS/LightRAG
★ 40,4402024-10-02PythonMIT
轻量双路检索（实体 + 关系），论文入选 EMNLP。工程上比 graphrag 好落地：依赖少、流程短、增量更新友好。
何时采纳要一个能在两周内跑起来的图检索基线时。

FalkorDB

B
FalkorDB/FalkorDB
★ 10,5052023-07-20RustNOASSERTION
用 GraphBLAS 稀疏矩阵做图计算的图库，主打 GraphRAG 场景的低延迟，Cypher 兼容。许可是 SSPL，商用需法务确认。
何时采纳图检索的延迟成为瓶颈、且能接受 SSPL 时。

LLM Graph Builder

B
neo4j-labs/llm-graph-builder
★ 5,2902024-01-11Jupyter NotebookApache-2.0
Neo4j 官方的「文档进图」工具：非结构化文本抽成实体关系写入图库。它是这一类里唯一提供「先声明 node/relationship 类型再抽取」的，尽管 schema 只进 prompt、不做拒绝。
何时采纳要从文档批量建图、并希望先约束抽取范围时。

Memgraph

B
memgraph/memgraph
★ 4,6362020-09-21C++NOASSERTION
内存图库，Cypher 兼容，面向实时多跳与流式场景。许可是 BSL，不是 OSI 认可的开源许可。
何时采纳需要内存级多跳延迟、且许可可接受时。

Graphify

B
Graphify-Labs/graphify
★ 139,2182026-04-03PythonApache-2.0
把代码库、文档、SQL、PDF 变成可查询的图，服务编码 Agent「查图代替 grep」。它明确不是 GraphRAG：无 embedding、无向量库、无社区摘要。边带 EXTRACTED / INFERRED 证据标签，这个设计可直接借。
何时采纳要给 Agent 提供「结构导航 + 证据标签」时。

PyGRAFT

B
nicolas-hbt/pygraft
★ 7172023-09-07PythonMIT
按给定的 OWL / RDFS 本体生成合成知识图，用于 KG 系统的基准测试。本体在这里是「生成器的规格」，不是运行时约束。
何时采纳需要造测试数据来验证 KG 流水线时。

BioCypher

A
biocypher/biocypher
★ 3422021-09-10PythonApache-2.0
生物医学知识图的统一构建框架，schema 驱动：先声明节点与边类型，再由适配器把不同数据源灌进图。它是「从 schema 生成物化图」最接近的现成骨架。
何时采纳要把多源数据按统一 schema 物化成图时。
