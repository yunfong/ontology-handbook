8.1 企业本体平台与 Palantir 复刻派

把 Foundry 的「对象类型 + 关系 + 动作 + 权限」四件套搬成开源实现

这是 2026 年最拥挤的一格。共同叙事是：Foundry 贵且重，但它的模式是可复制的——对象与链接负责「读」，动作负责「写」，权限与审计负责「敢不敢用」。这一格里真正把动作当一等公民的只有三个项目（Operational Ontology、BKN Foundry、Omnigraph），其余仍停在「建图 + 给 Agent 喂上下文」。

读法建议：先读 Operational Ontology 的四性质，把它当验收清单；再用其余项目检验这份清单缺了什么。注意本类 11 个项目里有 10 个建于 2026 年，API 会变、生产案例基本为零。

Operational Ontology

S
gura105/operational-ontology
★ 2022026-07-18TypeScriptMIT
把 Palantir Foundry 的 Ontology 从产品抽象成可独立讨论的模式，提出四条性质：语义对象与链接、动作门控写入、规则在动作上、写回权威源。配套的状态所有权三分法（source-backed / ontology-owned / derived）是同类材料里最实用的一张表。作者明说这是教学实现，不是框架。
何时采纳需要向团队解释「语义层与操作本体差在哪」时，用它当教材。

Palantir Ontology Strategy

S
Leading-AI-IO/palantir-ontology-strategy
★ 2462026-02-21—NOASSERTION
一本开源书（日英双语），把 Foundry 本体拆成「名词」（对象、属性、链接）与「动词」（动作、函数、动态安全），并把分支与评审流程算进本体本身。价值在二手拆解，不在产品功能清单。
何时采纳需要一份不依赖厂商话术的对外解释时。

Open Ontologies

A
fabio-rovai/open-ontologies
★ 2,2402026-03-09RustMIT
Rust 单二进制，把本体变更当基础设施变更管：plan → 爆炸半径报告 → apply → 回滚，并给审计者一份可自证的证书。README 的例子极具说服力：只加一条 domain 声明，不增删任何数据，却多出 901 条推论。
何时采纳设计「变更前先算影响面 + 变更后可复核」的流程时。

Omnigraph

A
ModernRelay/omnigraph
★ 1,8172026-04-10RustMIT
对象存储原生的图库，带类型化本体与 Git 式分支，向量 / BM25 / 图三路检索统一在一个引擎里。为「多个长周期 Agent 共享同一个世界模型」设计，Agent 只做无状态消费者。
何时采纳多个 Agent 并行写同一张图、需要隔离与合并时。

Context Ontology Accelerator

A
aws/context-ontology-accelerator
★ 1,0452026-07-28PythonApache-2.0
AWS 的语义上下文加速器，路线是 Scan（扫数据源、发现 schema）→ Model（归纳本体、定义指标）→ Serve（SPARQL 联邦 + MCP 供 Agent）。权限做成命名空间隔离加双层角色。工程很重：Python、Node、Java、Docker 四套工具链。
何时采纳要搭一整套语义上下文服务、且技术栈已在 AWS 上时。

Ontology Playground

A
microsoft/Ontology-Playground
★ 2,9882026-02-17TypeScriptMIT
微软的纯静态本体设计器与词表目录：Cytoscape 渲染、可视化编辑、RDF 导入导出，配一套任务式教程。零后端依赖，可直接托管。它的定位是「给眼睛看」，没有 API、校验、权限。
何时采纳评审会上需要一个能点、能缩放的图当讨论载体时。

Foundry Ontology Open

B
cloudbadal007/foundry-ontology-open
★ 1082026-03-22PythonMIT
Foundry 三层架构的 Python 复刻，把 Interface、Marking 这些容易被漏掉的概念也画进了分层图，并提供 OWL/SHACL 导出桥与 MCP server。但仓库只有 53 KB：三层架构加导出桥塞进这个体量，只能是骨架。
何时采纳需要一个完整的三层概念清单（含接口与标记）时。

BKN Foundry

B
openbkn-ai/bkn-foundry
★ 1,0402026-05-26GoNOASSERTION
Go 写的「本体后端基座」，K8s 部署，自带 BKN Lang 描述业务语义，把本体翻成 data / logic / actions / security 四类运行时服务。它是本类里少数把 actions 写进能力清单的项目。许可为多许可，商用前必须读原文。
何时采纳想看「本体如何变成服务」的重型实现时。

Helix Foundry

B
HelixDB/helix-foundry
★ 1,8522026-10-07GoApache-2.0
接数据库与文档，让 Agent 起草本体，审核后灌进 HelixDB。两个设计值得记：每个值都保留出处（表的某行或文档某句），以及两份文档冲突时不自动采信、进队列等人工裁决。本地版明说单人使用、无登录。
何时采纳研究「Agent 起草 + 人工审核 + 冲突裁决」流程时。

TrustGraph

B
trustgraph-ai/trustgraph
★ 2,8532024-07-10PythonApache-2.0
面向 Agent 的治理平台，主张把规则在「动作发生的点上」执行，并保留策略版本以复现每个结果。这两句话指向可审计系统的三个技术前提：动作点执行、策略版本化、结果可复现。
何时采纳设计「可复现的决策审计」时，借它的策略版本思路。

OpenFoundry

C
u485349-coder/OpenFoundry
★ 1522026-04-24—NOASSERTION
自称开源版 Foundry，README 是标准的产品落地页写法：五条卖点、四个行业场景、零架构内容。建库次日之后再无提交，GitHub 检测不到主语言。
何时采纳作为「营销语言包装本体」的反面样本使用。
